I've gone through the docs you pasted. The biggest mistake most teams will make is trying to build "another chatbot."
Aicoo is NOT a chatbot.
Aicoo is a Personal COO Operating System.
The docs reveal three important things:
Agent Layer = reasoning (/chat, /briefing, /strategies)
Pulse Layer = memory, context, sharing, automation, tools
A2A / Multi-Person Layer = agents talking to agents, humans talking to agents, shared context
Since you said you're building a multi-people system, that's exactly where the hackathon value is.
Source: the API docs, Pulse Layer share links, context accumulation, messaging tools, heartbeat automation, and Aicoo's positioning as a Personal COO.

This is the most important hidden piece.

The docs do NOT expose:

```txt
requiresApproval = true
```

or

```txt

```

API.

But product docs repeatedly mention approval.

Examples:

### Email Drafts

Docs say:

```txt

You approve
Edit

```

### Suggestions

Briefings return:

```json
{
  "title": "...",
  "description": "...",
  "action": "..."
}
```

Those are recommendations.

Not automatic execution.

### Integration Settings

The docs explicitly say:

```txt
Allow Aicoo to draft emails
but require review before sending
```

and

```txt
Create calendar events only with approval
```

This is massive.

Because it reveals their philosophy:

```txt
Human-in-the-loop
```

instead of:

```txt
Fully Autonomous
```
